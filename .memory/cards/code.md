# Code — game plugin

**Path:** `Code` · **Stack:** C++17, CRYENGINE 5.6 (Schematyc entity components), CMake+Ninja · **Size:** 11 files / ~1.2k LOC
**Entrypoints:** `GamePlugin.cpp` (`CGamePlugin`, an `ICryPlugin`), `Components/Player.cpp`
**Builds with:** `make build` (presets in `Code/CMakePresets.json`; VS Code still uses `build/gcc`) → `libGamePlugin.so` · **Tests:** none

## Purpose
The runtime game logic loaded by CRYENGINE's `GameLauncher`. Provides a first-person player (camera, movement,
input, shooting, debug screenshot), a spawn-point marker, a bullet projectile, and startup/level-load glue.
It does not generate assets and carries no gameplay content beyond the player loop.

## Structure
| Path | Holds |
|---|---|
| `GamePlugin.cpp/h` | plugin init, system-event listener, startup level auto-load, `goto` console command, level-load CVars |
| `StdAfx.cpp/h` | precompiled header — include first in every `.cpp` |

## Depends on
- external: CRYENGINE 5.6 headers/libs at `$CRYENGINE_DIR` — nothing builds without it
- internal: assets under `Assets/` (character `.cdf`, `.adb`, controller XML, levels) generated by `tools`

## Key flows
- Startup: `ESYSTEM_EVENT_GAME_POST_INIT` → `map <kStartupLevel> s` (not in editor) → `LEVEL_LOAD_END` sets `e_WaterOcean 0`, `e_WaterOceanBottom 0`, `e_TerrainLodErrorRatio 0.001`, `e_TerrainLodDistanceRatio 4.0`.
- Player: `Initialize()` builds character controller + advanced animation component from `firstperson.cdf`/`FirstPerson.adb`; camera follows the `head` joint, falling back to Z=1.8 m when no character loads; bullets spawn at the `barrel_out` attachment.
- Quit: ESC sets `m_quitRequested`; `Quit()` runs on the next update tick, not in the input callback.
- Debug screenshot: `K` toggles debug mode, `P` calls `TakeDebugScreenshot()` which drives engine `CaptureFrameBuffer` via `capture_*` CVars into `Screenshots/`.

## Gotchas
- `e_TerrainAutoGenerateBaseTexture` must **not** be set here for pipeline levels (blacks out terrain); it was removed from `LEVEL_LOAD_END`.
- GCC 14 `-Wrange-loop-construct`: use `const auto&` in the `GamePlugin.cpp` loop.
- Not adding a new file to `CMakeLists.txt` silently skips it.
- Several screenshot/engine fixes live in the **engine tree**, not here (see `debugging.md`).
